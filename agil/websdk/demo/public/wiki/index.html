Руководство AgilFrame

Развёртывание, проведение встреч, встраивание звонков и эксплуатация кластера.

Быстрый старт

  1. Для локального запуска нужны Node.js и npm. Установите зависимости, соберите пакеты, задайте API-ключ организации и секрет токенов через окружение. Запустите Core из корня репозитория.
npm ci
npm run build
npm start
  1. Откройте панель управления, укажите базовый URL, ID организации и её API-ключ. Создайте комнату в разделе «Комнаты» и сгенерируйте отдельную ссылку гостя. Для разработки контракта откройте интерактивный API.
  2. Для самостоятельного размещения используйте комплект Docker Compose. Задайте постоянный том данных, HTTPS, внешний URL, разрешённые origin, политику анонимного доступа и резервное копирование до выдачи приглашений. Веб-интерфейсы доступны напрямую. Рекламный сайт собирается отдельно при необходимости.

Пользователь может попасть в одну и ту же комнату через приглашение, iframe или SDK. Поведение определяется конфигурацией организации, переопределениями комнаты и разрешениями токена. Приложение-хост также может настроить внешний вид. Проверяйте эти уровни, если кнопки или тема различаются между двумя ссылками.

Встречи

Организатор

Создайте комнату, выберите режим и лимит, проверьте права гостя. При необходимости включите лобби или пароль. Передайте гостевую ссылку, а ссылку организатора храните отдельно. На экране входа проверьте устройства. Во время звонка кнопки микрофона и камеры меняют состояние, стрелки рядом открывают выбор устройства. Не поместившиеся действия находятся в «Ещё», участники и некоторые панели открываются из шапки.

В звонке с подключённым SFU откройте «Качество» в шапке, если этот элемент включён настройками комнаты. Режим «Автоматически» учитывает размер плитки и сеть. Ручной выбор меняет запрашиваемый слой входящего видео для вашего клиента. Фактическое разрешение зависит от слоёв, которые публикует собеседник.

Чат, демонстрация, доска и опросы

В чате отправьте пробное сообщение и файл. Для демонстрации выберите окно, вкладку или экран в браузере. Остановите её из панели звонка. Если включены доска и аннотации, проверьте их у участника с другой ролью. Для опроса задайте вопрос, варианты и правила выбора, затем проверьте голос гостя и закройте голосование.

Подкомнаты

Организатор или модератор открывает «Подкомнаты» в звонке, задаёт число групп и длительность. В режиме «Вручную» выберите подкомнату рядом с именем участника. Оставьте «Автоматически» для тех, кого система может распределить сама. После кнопки «Запустить» участники переходят в выбранные подкомнаты. Если разрешён самостоятельный возврат, в подкомнате доступна кнопка «Вернуться». Действие «Закрыть все» возвращает оставшихся участников в основной звонок.

Запись

Включите запись в настройках комнаты и дайте право нужной роли. Проверьте диалог согласия, индикатор записи у гостя, остановку и полученный файл. Локальная запись работает через браузер, запись на медиасервере использует Egress.

Фон камеры

Нажмите стрелку у камеры, выберите «Изображение» и готовый фон, затем нажмите «Применить». Для своего фона нажмите «Загрузить свой» и выберите JPG, PNG или WebP до 12 МБ. Файл обрабатывается в браузере. В следующем звонке в том же профиле и на том же сайте фон будет доступен в списке под названием «Мой фон».

Организации и доступ

Храните ключ организации на сервере приложения. Для участников выдавайте короткоживущие токены с комнатой, ролью и идентификатором. Настройте разрешённые origin для WebSocket и iframe, затем проверьте вход извне с каждого разрешённого домена. При использовании SSO настройте клиента OIDC у провайдера и проверьте точный redirect URI.

Для зала ожидания откройте звонок в двух профилях. В профиле организатора откройте список ожидающих. В профиле гостя нажмите «Отменить заявку» и убедитесь, что строка исчезла у организатора. Затем создайте новую заявку и проверьте допуск и отказ. Для файлов и записей проверьте права двух разных ролей и истечение подписанных ссылок. При изменении политик сверяйте результат с журналом аудита.

В корпоративной интеграции создавайте звонок с allowedParticipantIds и выдавайте индивидуальный токен через сервер компании после проверки сессии пользователя.

Встраивание

Для стандартного интерфейса используйте iframe или SDK. Передайте URL сервера, организацию, комнату и короткоживущий токен, выданный вашим backend. Для iframe задайте разрешения браузера на аудио, видео и демонстрацию, а обмен сообщениями выполняйте по задокументированному контракту.

Для своего интерфейса используйте headless SDK. Подпишитесь на состояние и события, сопоставляйте удалённые потоки с ID участника, освобождайте локальные обработчики при выходе. Начните с проверки двумя профилями. Сверьте появление удалённых кадров, доставку сообщений, результат переключения камеры и завершение звонка.

Оформление

В редакторе задайте бренд, тему, фон, расположение и набор элементов. Проверьте превью в светлой и тёмной теме и на ширине телефона. Экспортируйте конфигурацию для ревью, сохраните в нужной организации и откройте новую комнату для проверки. Для полного кадра используйте contain. При заполнении плитки через cover границы изображения могут обрезаться.

Медиа и трансляции

Для личного звонка доступен прямой P2P, для групповых комнат включите LiveKit и профиль ёмкости. Проверьте камеру, микрофон и удалённое видео в двух сетях. Для ограниченных корпоративных сетей настройте TURN и проведите отдельный тест через relay.

Для серверного HLS, MP4 и RTMP разверните Egress worker на отдельном узле, подключите его к Redis и SFU. Для HLS и MP4 подготовьте приватное хранилище и подписанное воспроизведение. Создайте тестовую комнату, запустите трансляцию с источником, проверьте плейлист и сегменты, затем остановите задачу. Для SIP понадобится отдельный сервис и данные транка.

Адрес публикации и разрешение зрителя выдаются отдельно.

Маршрутизация трансляции

В панели администратора откройте «Интеграции → Масштабирование», найдите «Трансляция» и выберите «Протокол для зрителей». Для HLS укажите адрес .m3u8, для WebRTC — HTTPS-адрес WHEP. Сохраните настройки организации, откройте комнату и проверьте плеер в блоке «Запись и трансляция». HLS и WebRTC могут иметь разные адреса, поэтому сохранение выбора WHEP не меняет HLS-плейлист.

  • Массовый просмотр звонка или демонстрации экрана. Участники и ведущий остаются в комнате. Настроенный Egress выдаёт HLS, который зрители открывают через плеер без входа в комнату. Для открытой аудитории подключите CDN. Для закрытой выдайте подписанную ссылку и проверьте срок действия. Если ведущий демонстрирует вкладку с аудио, включите передачу звука в диалоге браузера и проверьте звук у зрителя отдельно.
  • Игровой или другой эфир с низкой задержкой. OBS может публиковать по WHIP, а GStreamer — по RTP в доверенной сети или по SRT на Edge. Для WHEP используйте совместимые H.264 и Opus. Когда есть только AAC, преобразуйте звуковую дорожку на Edge. Проверьте доступность HTTPS и ICE для зрителя. Внешний WHEP-адрес должен принимать SDP POST и разрешать origin плеера через CORS. При использовании отдельного origin откройте заголовок Location, чтобы плеер мог завершить сессию на сервере.

Тренинг с ведущими и зрителями

  1. Создайте групповую комнату для ведущих. В комнате звук, камеры и демонстрация экрана идут по WebRTC. Ведущие могут общаться в реальном времени с демонстрацией или без неё.
  2. Для массового просмотра запустите отдельный выход комнаты через Egress и передайте зрителям HLS-ссылку. Зрители открывают плеер с задержкой и не занимают места в медиакомнате. Для закрытого обучения используйте выдачу защищённых ссылок.
  3. Для обращений зрителей нужен отдельный чат или очередь вопросов, доступные из страницы просмотра. Встроенный чат звонка доступен участникам комнаты. Зрительский чат в самом HLS-плеере остаётся отдельной задачей.

В демо публичных эфиров OBS зрительский чат работает отдельно. Он хранит до 100 000 комментариев на эфир в локальном SQLite. Кнопка «Ранние сообщения» загружает предыдущую страницу. Комментарии записанного эфира доступны до истечения срока повтора. На отправке действуют ограничения частоты и повторов. Если оператор подключил CAPTCHA, пройдите проверку перед отправкой первого комментария. Организатор открывает блокировки в окне «Модерация эфира». Список под чатом можно включить отдельно. IP или подсеть раскрываются кнопкой «i».

Настройка Egress

Через окно «Модерация эфира» организатор может ограничить ссылки и добавить запрещённые фразы. Бан включает запрет отправки для конкретного зрительского пропуска до конца эфира. Смайлики вставляются кнопкой рядом с полем сообщения.

Субтитры и ИИ

Выберите браузерное либо серверное распознавание и разрешённые языки. Для серверного провайдера настройте endpoint или локальную модель, затем проверьте речь двух участников. Настройте отдельно перевод, заметки и ассистента, проверьте доступ нужной роли и политику хранения результата.

В звонке откройте «Ассистент» с панели или из «Ещё». Можно спросить, где выбрать микрофон, и запросить доступные действия. При запуске записи откроется штатный диалог согласия. Для внешней модели настройте провайдер организации и проверьте ответ через MCP.

Проверка разговора

В панели откройте комнату и вкладку «Проверка разговора». Включите субтитры, добавьте правила общения и раскрытия данных и задайте срок хранения сигналов.

Core анализирует новые финальные субтитры после согласия всех участников. Отзыв согласия очищает сигналы. В E2EE-комнатах проверка недоступна. Запись и заметки ассистента настраиваются отдельно.

Отчёт содержит время, код правила, категорию и приоритет. Совпадения проверяет человек. После закрытия комнаты отчёт доступен администратору организации по API до истечения срока.

Большие комнаты и HA

Профиль ёмкости задаёт лимит комнаты и бюджет видеоподписок. Измеряйте SFU и сеть отдельно от числа WebSocket. Для резервирования Core задайте общий Redis, одинаковый AGIL_CLUSTER_ID, разные AGIL_CLUSTER_NODE_ID и одинаковые параметры подписи токенов. Для восстановления комнат между узлами с раздельными дисками включите AGIL_ROOM_SNAPSHOT_STORE=redis. Маршрутизируйте запросы на лидера и проверяйте takeover с реальной комнатой. Текущий режим использует одного лидера Core. HA медиасервера и восстановление WebRTC после отказа SFU проверяются отдельно.

Эксплуатация

Перед обновлением сохраните версию образа и данные, прогоните проверки на тестовом стенде. После выкладки проверьте /v1/health, авторизацию в панели, создание комнаты, вход двух клиентов, видео, звук и функции, включённые в этой поставке. При сбое соберите HTTP-код, тип комнаты, профиль SFU и результат применения конфигурации. Для диагностики HLS отдельно проверьте источник, worker, хранилище и плеер.
